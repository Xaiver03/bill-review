# billkit 文档维护标准

> 状态：Active
> 最后核验：2026-11-20

## 1. 文档类型与唯一位置
| 类型 | 目录 | 回答 |
| --- | --- | --- |
| 架构与信息架构 | `docs/01-architecture/` | 系统如何工作、分层与边界 |
| 使用流程 | `docs/02-workflow/` | 分类/复核/导出怎么走 |
| 参考资料 | `docs/03-reference/` | 字段、导出目标映射 |
| 操作指南 | `docs/04-guides/` | 如何安装、运行、排障、贡献 |
| 项目记录 | `docs/05-project/` | 某次实现/验收实际发生了什么 |
| 计划 | `docs/plans/` | 下一步做什么 |

同一主题可有多类文档，但每类只留一个活动入口；不把完成报告当架构说明，不在指南里维护进度。

## 2. 元数据
活动文档标题下三行：`> 状态` / `> 最后核验：YYYY-MM-DD` / `> 权威实现：path`。中文优先。

## 3. 事实表述
`已实现`（源码+测试可证）/ `可调用`（跑通过一次）/ `完成`（验收项全满足）。只证明构建通过就写「本地构建通过」。

## 4. 历史与安全
被取代的文档从工作树删除，由 Git 历史保存；不建 archive/backup/old 副本目录。禁止提交真实账单、银行卡号、证件号、Token。
