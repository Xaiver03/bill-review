# 产品原则

> 状态：Active · 最后核验：2026-11-20

- **"批量处理"是能力，不是定位。** 用户为"省下的时间 + 能直接用的干净账本"停留，不为"又一个记账 app"。
- **上游、出口中立。** billkit 给账簿喂数据，不替代账簿；出口（木木 / Firefly / beancount）可插拔，进口（微信 / 支付宝 / 银行脏格式适配）才是护城河。
- **主对象是批次（batch），不是单笔交易。** 批次是产品骨架：接入 → 清洗/去重 → 分类 → 复核 → 导出 → 归档 → 增量。
- **批量默认，单条例外。** 默认全自动，只把不确定 / 异常 / 新商户挑出来让人看。
- **复利在知识库。** 每次人工判断沉淀为可移植的商户→分类知识库，让下一批自动率单调上升。
- **护城河是适配器广度 + 脏数据鲁棒性**，不是分类算法；分类算法是可替换件。
- **诚实对待商业化。** 纯本地开源工具清晰变现难，不为"产品化"硬造订阅。
- 完整方案见 [产品化方案](../plans/productization.md)。
